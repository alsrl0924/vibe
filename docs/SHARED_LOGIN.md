# 학습앱 이동 메뉴와 공유 로그인

2026-11-07 사용자 요청 구현. 로컬 검증 완료 단계이며 이 작업의 푸시·배포는 아직 승인받지 않았다.

## 동작

세 앱 상단 '다른 학습앱' 메뉴에서 /netstudy/, /linuxstudy/, /vibe/로 이동한다. 작은 화면에서는 아이콘으로 표시하고 현재 앱에 체크 표시한다. 일반 링크로 전체 페이지를 열어 서로 다른 Next 앱과 정적 앱의 런타임을 섞지 않는다. Linux 1차/2차 전환도 전체 페이지 이동으로 데이터와 진행 세션을 새로 바인딩한다.

같은 https://alsrl0924.github.io 오리진·같은 브라우저 프로필에서 공통 Supabase 세션을 사용한다. 서로 다른 기기·시크릿 창의 최초 로그인까지 자동 공유하지 않는다.

## 인증과 이전

- 공용 프로젝트 lkokgqqhsppezflqkbgx만 사용. 다른 프로젝트 URL은 두 문제은행의 구성 검사에서 거부한다.
- 공통 인증 키 sb-lkokgqqhsppezflqkbgx-auth-token. 네트워크관리사의 기존 기본 키를 유지한다.
- lib/shared-auth-core.cjs와 Vibe js/shared-auth-core.js는 같은 정책의 동일 바이트 파일이다.
- 기존 공통 로그인이 있으면 그 계정을 유지한다. 공통 키가 없고 Linux/Vibe의 기존 로그인 계정이 하나로 일치하면 그 세션을 한 번만 옮긴다. 서로 다른 계정이 있으면 임의 선택하지 않고 새 로그인을 받는다.
- 인증 이전 완료 마커를 남겨 로그아웃 후 기존 키에서 오래된 로그인이 되살아나지 않게 한다. 이전 키는 보존한다. 토큰을 URL·로그·문서에 복사하지 않는다. JWT issuer 검사는 이전 대상 구분용이며 권한 검증을 대체하지 않는다. 실제 인증과 DB RLS는 Supabase가 담당한다.
- signOut scope local은 이제 같은 세션을 쓰는 이 브라우저의 세 앱에 공통으로 반영한다. 다른 기기의 세션을 일괄 종료하지 않는다.
- 계정 변경 시 이전 동기화를 무효화하고 입력을 잠근 다음 새 페이지를 연다. 늦게 돌아온 이전 계정의 응답은 현재 화면에 적용하지 않는다.

## 학습 기록 보존

앱별 DB 표/app_id와 기존 문제 ID는 유지한다. 두 문제은행의 기기 기록·이어 풀기 키에 :user:<uid> 접미사를 붙여 계정별로 구분한다. 원래 키는 게스트/이전 기록으로 그대로 보존한다. 로그인 후 '이 기기의 기존 기록 가져오기'를 선택·확인한 경우에만 계정 기록에 합친다. 기존 무기명 기기 기록을 로그인 계정에 자동 귀속하지 않는다. Vibe는 기존 계정별 기록 구조를 유지한다.

현재 Supabase의 데이터·정책·스키마·Google 설정에는 변경이 없다. 로컬 가상 계정 검사에서는 실제 Supabase 요청을 모의 응답으로 바꿨으며 가상 JWT는 localhost:4193에서만 사용했다.

## 검증

- Linux 12개, Network 12개, Vibe 19개: 총 43개 자동 검사 통과. 인증 이전, 기존 로그인 우선, 계정 충돌, 로그아웃 후 재접속, 계정별 키, 늦은 계정 응답, 오프라인 기기 학습, 캐시 격리를 검사했다.
- 두 Next 앱의 변경 파일 ESLint 및 production 정적 export 빌드 통과. Vibe의 추가/변경 JS와 HTML 인라인 문법 검사.
- 가상 계정 A로 Network → Linux → Vibe 이동 시 동일 로그인 및 모의 동기화 완료 확인.
- Vibe A의 클립 1개 → B에서 0개 → A로 돌아오면 1개 복원 확인.
- Linux 1차 A의 클립·이어 풀기 → B에서 비어 있음 → A에서 복원 확인.
- Vibe에서 로그아웃하면 다른 탭의 Linux도 로그인 화면으로 전환됨을 확인.
- 320px 모바일에서 세 메뉴를 확인하고 용어집 팝오버의 화면 밖 잘림을 수정했다. 뷰포트는 검사 후 기본값으로 복구했다.
- 세 서비스 워커는 자기 앱 캐시만 정리하고 다른 앱 파일/인증 응답을 캐시하지 않도록 제한했다.
- 학습 문제·보기·정답·해설·이미지 데이터는 변경하지 않았다. 미배포 Linux 해설은 원래 체크아웃에 그대로 남겼다.

## 배포 전/후

사용자가 명시적으로 배포를 요청하면 세 저장소의 최신 원격 변경을 확인하고 이 기능 커밋만 반영한다. 권장 순서는 Network → Linux → Vibe. 원래 Linux main의 미배포 해설을 함께 푸시하지 않는다. Supabase URL/Google redirect는 기존 설정을 유지한다. 세 앱 모두 새 버전으로 새로고침한 후 로그인 공유를 검증한다.

실제 Google OAuth 왕복과 실제 서버에서 새 공유 세션의 저장/복원은 배포 후 사용자 로그인으로 별도 확인해야 한다. 로컬 가상 계정 결과를 실제 Google 로그인 완료로 보고하지 않는다.

검사용 서버/제어 페이지는 앱 저장소 밖 .migration-work/navigation-preview.cjs, navigation-fixture.js 및 http://127.0.0.1:4193/fixture/에 있다. 가상 계정·통신 대체 파일을 배포 산출물이나 Git에 넣지 않는다.

## 롤백

세 앱의 기능 커밋만 되돌린다. 공통/이전 인증 키, 계정별 캐시, 게스트 원본 및 서버 기록은 삭제하지 않는다. 이전 앱은 계정별 신규 캐시를 직접 읽지 않으므로 롤백 시 기록을 무명 게스트 키로 덮어쓰지 않는다.
